# ローマ字タイピング練習

### https://kanahii.github.io/typing/

> このページは Claude Code を使って生成・実装しています。
> 動作確認済みですが、私はコードの中身についてほとんど把握していません。

日本語入力の練習ページ。上の URL を開けばそのまま使えます。インストールは
要りません。読み込んだローマ字テーブルやお題がサーバへ送られることもなく、
ブラウザの中だけで完結します。

HTML + プレーンな JavaScript のみ（ビルド不要・外部ライブラリなし）。

ローマ字テーブルとお題は「設定」から差し替えられます。テーブルは Google
日本語入力と同じタブ区切り形式なので、AZIK・月・薙刀式のような独自配列の
テーブルをそのまま読ませて練習できます。

- 打鍵の判定は `event.code`（物理キー位置）で行うので、**1 つのテーブルが
  JIS / US 両方で動きます**
- 次に押すキーは画面内のキーボードが示します。キーに出るのは刻印ではなく
  **いまそのキーを押したら入力される文字**です
- BackSpace は Google 日本語入力と同じく、**表示上の 1 文字**を消します
- 最短の打鍵数との差を「短縮余地」として出します

## 手元で動かす

clone して、**ローカルサーバ経由で**開きます。ES モジュールを使うので、
`file://` では CORS に阻まれて読み込めません。

```bash
python -m http.server 8000
```

その後 `http://localhost:8000/` を開きます。

## キーボード配列（JIS / US）

打鍵の判定は `event.key` ではなく **`event.code`（物理キー位置）**で行います。
`event.key` は OS の入力ロケール適用後の文字なので、同じ物理キーでも JIS 設定
なら `:`、US 設定なら `;` になり、どの物理キーかも分かりません。

テーブルは文字（`;` `:`）で書き、実行時に配列別の変換表を通して物理キーへ
解決します。これで **1 つのテーブルが JIS / US 両方で動きます**。

| 文字 | JIS | US |
| --- | --- | --- |
| `;` | Semicolon | Semicolon |
| `:` | Quote | Semicolon + Shift |
| `@` | BracketLeft | Digit2 + Shift |
| `[` | BracketRight | BracketLeft |

配列は「設定」の先頭で選びます。**誤設定だと `;` 系が全滅する**ので、選んだ
ものは localStorage に覚えます。ブラウザから物理配列は検出できないため自動
判定はできません。

変換表は `core/layout.js` の 1 箇所だけにあります。実機で `code` が想定と
違っていたら、`keycheck.html` で確認してここを直してください。

### 配列によって案内が変わる場合

同じ文字でも、配列によって Shift が要るかどうかが変わります。長音「ー」は
AZIK では `:` でも `-` でも出せますが、JIS の `:` は Shift 無し、US の `:` は
Shift + `;` です。

そこで**同じ打鍵数の経路が複数あるとき、Shift の要らないキーを優先**します。
打鍵数を犠牲にはせず、同点のときだけ効く順序付けです（同点かつ Shift も同じ
なら、テーブルの定義順が早いほう）。テーブルを配列ごとに分ける必要はありません。

| よみ | JIS の案内 | US の案内 |
| --- | --- | --- |
| もーたー | `mo:ta:` | `mo-ta-` |

配列を渡すのは `Layout.routeOpts(layout)` で、経路計算のキャッシュ鍵にも
配列 ID が入ります。

## ローマ字テーブル

「設定」からタブ区切りテキストを読み込むと、入力パターンを差し替えられます。
Google 日本語入力のローマ字テーブルと同じ形式です。

```
入力	出力	次の入力
```

```
sa	さ
si	し
tt	っ	t
nk	ん	k
```

- `入力` が重複した場合、後に定義した行で上書きされます。
- `出力` と `次の入力` がどちらも空の行はコメントとして無視されます。
  判定は空かどうかだけなので、`#` で始めてもタブと出力があれば規則として
  読まれます。コメント行にはタブを入れないでください。
- 文字コードは UTF-8 / UTF-16 / Shift_JIS を自動判定します。

### タグ列

4〜6 列目に、省略可能なタグ列を置けます。

```
入力	出力	次の入力	第1	第2	第3
sya	しゃ		sei,row.sa	you,row.sha	std,dan.a
```

このページでは全タグが有効なので、付いていても付いていなくても打てるものは
変わりません。打ち方を段階的に解禁していく用途のために読めるようにしてある
もので、タグ列のあるテーブルをそのまま読ませても壊れません。

### かなの点検

独自のテーブルを書くと、どこかの行を書き落としていても気づきにくいものです。
「設定」の**「かなの点検」**を押すと、かなを一通り並べたお題
（`sample-problems/kana-check.tsv`）と突き合わせて、打てないものを挙げます。

```
かなの点検: 47 件すべて打てます
かなの点検: 47 件中 3 件が打てません — 小書き や行 / 記号 / 外来音 ヴ行
```

出題は入れ替えません。結果を出すだけです。

点検用のお題は「清音 か行」「外来音 ファ行」のような単位で並べてあるので、
落ちた名前がそのまま足りない範囲になります。お題ファイルとして読み込んでも
かまいません（その場合は「出題数」を件数以上にしてください）。

## 経路計算

中核となる計算は 1 つだけです。打鍵中の案内、お題の採否、プレイ後の
フィードバックが、これ 1 本を共有します。

> かな列と（絞り込まれた）テーブルを与えると、最短の打鍵列と、そこで使われた
> タグを返す

```js
import { plan, compare } from './core/route.js';
const opts = Layout.routeOpts(layout);   // 同点のときの Shift 優先に使う
plan(table, 'かん', opts);   // { ok, cost, keys, tags, tagCounts, consumesMultiple, reason }
```

`tagCounts` は「そのタグが経路上に何回出たか」です。

`compare` は、絞り込んだテーブルと元のテーブルで経路長を比べます。

```js
compare(fullTable, subsetTable, 'かん', opts);   // { stage, full, reducible, reason }
```

**短縮余地 = 絞り込んだテーブルでの打鍵数 − 元のテーブルでの打鍵数**。
その部分集合では届かない近道がどれだけあるか、という量です。

| テーブル | `かん` の最短 | 短縮余地 |
| --- | --- | --- |
| AZIK の撥音拡張を外したもの | `kann`（4 打） | 2 |
| AZIK 全体 | `kz`（2 打） | 0 |

真偽値ではなく判定理由を含む結果オブジェクトを返します。設計時のフィルタで
「なぜこの文が落ちたか」を人に見せる必要があるためです。

`次の入力` は、変換後に入力欄へ残す文字列です。`tt → っ (次: t)` なら
`tta` が「った」に、`nk → ん (次: k)` なら `nka` が「んか」になります。

**「次の入力」に残った文字も入力の一部**です。`出力` を一度も経由しない
かなも入力できます。例えば次のテーブルでは `ka` が未定義でも、`k` だけで
「か」が入力できます（`k` を打つと入力欄に「か」が残るため）。

```
k		か
かi	き
かu	く
```

### 同じ打鍵数の経路が複数あるとき

打鍵数が同じなら、次の順で選びます（前の方が強い）。**打鍵数は決して犠牲に
しません。**

| | 見るもの | 理由 |
| --- | --- | --- |
| 1 | 呼び出し側が優先を指定したタグ（`opts.prefer`） | 特定の打ち方を案内に出したいとき |
| 2 | Shift が要らない（`opts.shiftOf`） | どちらが楽かは配列で変わる。テーブルを配列別に分けずに済ませる |
| 3 | テーブルの定義順が早い（`ord`） | 最後の決め手。テーブル側で明示的に決められる |

1 が要るのは、独自配列の互換キーが標準の打ち方と**打鍵数が同じ**ことが
あるからです。AZIK の `kga`（拗音互換）と `kya` は 3 打で並ぶので、定義順
しだいで案内に出たり出なかったりします。

```js
import { withPrefer } from './core/route.js';
plan(table, 'きゃく', withPrefer(Layout.routeOpts(layout), ['alt.you']));
```

同点の順位づけなので、優先しても打てない打ち方は出てきません。「ぎゃ」に G の
形が無ければ `gya` のままです。

指定しない場合（このページの既定）は 2 と 3 だけで決まります。

## 画面

```
今日はいい天気ですね          ← お題 (表示文)
きょうはいいてんきですね      ← よみ (見本。減らず、次に打つかなに印。
                                 まとめて確定する分はまとめて印)
──────────────────
入力
きょうはいい|                 ← 入力欄。空から増えていく
[ キーボード図 ]              ← 次に押すキー / 押されたキーを表示
```

次に何を打つかはキーボード図が示します。ローマ字ガイド (打鍵列を淡色で
消費していく表示) もありますが、既定ではオフです → [ローマ字ガイド](#ローマ字ガイド)

よみの印は、**1 回の確定でまとまって入力されるぶん**に付きます。`きゃ` は
`kya` の 1 回で確定するので `きゃ` にまとめて印が付きます。何文字ぶんに
なるかはローマ字テーブル次第です。

ただし `次の入力` で続けて入力される分は含みません。`tt → っ (次: t)` なら
`った` ではなく `っ` だけに印が付きます (`た` は次の打鍵で確定するため)。

入力欄には次の 3 つが並びます。

| 表示 | 意味 |
| --- | --- |
| 一致している入力 | よみと合っている先頭部分 |
| ずれた入力（赤地） | よみと合わなくなった部分。消すまで残る |
| 未確定のローマ字（点線） | 変換待ち。`きょ` を打つ途中の `ky` など |

### キーボード

読み込むテーブルによっては、ローマ字表記とかけ離れたマッピングになります。
その場合ローマ字ガイドは読みづらいので、キー位置でも示せるようにしています。

キーに出るのは**刻印ではなく、いまそのキーを押したら入力される文字**です。
ローマ字テーブルと現在の入力状態から毎回計算します。

```
バッファが空   … A に「あ」、I に「い」、K に「k」
k を打った後   … A に「か」、I に「き」、K に「っk」、Y に「ky」
ky を打った後  … A に「きゃ」、O に「きょ」
```

打ちかけが消えるキー（`k` の後の `s` など）は暗く落とします。
`k → 次の入力 か` のようなテーブルなら、K キーには最初から「か」が出ます。

**Shift を押している間は、シフト側で入る文字に切り替わります。** `/` と書かれた
キーを見ながら打って `?` が出てくるのは不可解なので、押している修飾に合わせます。
その配列で Shift を押しても何も入らないキー（JIS の `0` など）は空になります。

| 表示 | 意味 |
| --- | --- |
| 黄色の枠 | 次に押すキー。Shift が要る文字なら Shift も光ります |
| 水色 | いま押したキー（正解） |
| 橙色 | いま押したキー（より少ない打鍵で打てる打ち方がある） |
| 赤 | いま押したキー（ミス） |
| F と J の下線 | ホームポジションの目印 |

### より短い打ち方があるとき

同じかなでも打鍵数が変わる打ち方があります。速く打っていると気づかないので、
**より短い打ち方があるときだけキーを橙色**にしています（通常より少し長く
点灯します）。打鍵数が変わらない打ち方は普段どおりの水色です。

| 打ち方 | 判定 |
| --- | --- |
| `しゃ` を `sya` / `sha` | どちらも 3 打鍵 → 水色 |
| `じゃ` を `zya` | `ja` で済むので `z` の時点で橙色 |
| `じゃ` を `jya` | `y` の時点で橙色 |
| `った` を `ltu` + `ta` | `l` の時点で橙色（2 打鍵ぶん増えるため） |
| `にちは` を `chiha` | `tiha` で済むので `c` の時点で橙色 |

減らせる打鍵数の合計は、結果画面に「短縮余地」として出ます。

これは**お題を打ち切った時点の入力**で数えます。打鍵ごとの積み上げではなく、
「そのお題を打ち終えるのに使った打鍵数」と「理論値」の差です。そのため、
橙色に気づいて BackSpace で最短の打ち方に直せば加算されません。
何度打ち直しても、最後に残った打ち方だけが数に入ります。

| 打ち方（`じゃんけん`、理論値 7 打鍵） | 橙の点灯 | 短縮余地 |
| --- | --- | --- |
| `jankenn` | 0 | 0 |
| `zyannkenn` | 2 | 2 |
| `zya` → BackSpace → `jankenn` | 1 | 0 |
| 遠回りと打ち直しを 3 回繰り返して最後は最短 | 3 | 0 |
| 最短に直してから、また遠回りで打ち切る | 3 | 2 |

入力がお題からずれている間は、次に押すキーとして **BackSpace** が光ります。

キーボードとローマ字ガイドの表示 / 非表示は「設定」→「表示」で切り替えます。
配列（JIS / US）は「設定」のいちばん上です。

### ローマ字ガイド

打鍵列を並べて、打ち終わった分を淡色にしていく表示です。**既定ではオフ**で、
「設定」→「表示」から出せます。

出るのは**実際に押すキー**です。未確定バッファの中身ではないので、
`ky → 次の入力 きy` のようなテーブルでも `ky` と出ます（`きy` は出ません）。

オフにしている理由は次の 2 つです。

- 最短の打鍵列に **BackSpace が必要になるテーブルがある**。ローマ字の並び
  だけでは表せません（`ky → 次の入力 きy` のようなテーブルでは、`き` を
  単独で入力するのに BackSpace が要ります）
- 有効打鍵としての BackSpace と、ミスの修正・打ち直しの BackSpace を
  区別する必要が出てしまう

なお現在の最短打鍵の計算は **BackSpace を使わない前提**です。そのため、
BackSpace が要るお題は「打てない」と判定されて除外されます。

### ミスタイプ

**打ち間違えてもローマ字変換は止まりません。** 打鍵はテーブルどおりに
変換され続け、その結果が入力欄に出ます。「その打ち方をすると代わりに何が
入力されるのか」がそのまま見えます。

| 打ちたいもの | 実際の打鍵 | 入力欄 |
| --- | --- | --- |
| `きょ` | `kya` | `き` + **`ゃ`**（赤） |
| `で` | `da` | **`だ`**（赤） |
| `さ` | `ta` | **`た`**（赤） |

よみとずれた時点でミスに加算され、枠が赤くなります。ずれたまま打ち続けても
変換は続き（そのつどミス加算）、BackSpace で消すまで先へは進めません。

テーブルのどの規則にもならない打鍵（`kd` の `k` など）は、変換されずに
その文字のまま入ります。これも IME と同じ挙動です。

### 判定について

打鍵はまず IME と同じ要領でテーブルにかけ、変換結果を積んでいきます
（目標とは無関係に、常にテーブルどおり）。そのうえで、積まれた入力を
お題のよみと突き合わせて正誤を決めます。

- 入力がよみの先頭一致のままで、かつ残りを打ち切る打鍵が存在する … 正解
- よみからずれた／未確定のバッファがどう転んでもよみにならない … ミス

「残りを打ち切れるか」は、テーブルを実際にシミュレートして探索します。
`し` = `si` / `shi` / `ci` のような複数表記も、`k` → 「か」のような
「次の入力」経由の入力も、まとめてこの探索で扱われます。どの打ち方でも
正解になります。

キーボードが示す「次に押すキー」は、**最短の打鍵数**になる打ち方です。同じ
打鍵数の打ち方が複数ある場合は、テーブルで**先に定義した行**が使われます
（`しゃ` は `sya` と `sha` のどちらでも 3 打鍵ですが、`sya` が案内されます）。

既定テーブルは単独の `n` を「ん」にしていません（Google 日本語入力と同じく
`nn` / `n'` / `n` + 子音）。単独の `n` を許したい場合は、`data/romaji-default.js`
または読み込むテーブルに `n<TAB>ん` の行を追加してください。

## フィードバック

合否判定は設けず、情報として出します。

| | |
| --- | --- |
| 打/分 | 打鍵数 ÷ 経過時間 |
| 打鍵 / ミス / 正確率 | BackSpace は打鍵にもミスにも数えません |
| 短縮余地 | 打ち切った時点の打鍵数と理論値の差 |

短縮余地が 0 でないときだけ、どこで縮められたかの案内が出ます。ただし
短いほうが常に良いとは限りません（`ん` を `nn` に統一して例外を無くす、
といった打ち方もあります）。目立たせすぎないようにしてあります。

## お題

既定は 200 問（日常の短文 / ことわざ / 仕事 / 早口言葉 / 文学 / 技術 /
拗音・促音・濁音が多めの文 / 季節 / かたかな語 / 数字）。すべて普通の文で、
かなを並べただけの練習用のものは入れていません。1 回に出す数は「設定」の
「出題数」で変えられます。

「設定」からタブ区切りテキストを読み込むと差し替えられます。

```
表示文	よみ
```

- `よみ` を省くと、表示文をそのまま打つことになります
- `#` で始まる行と空行は読み飛ばします
- よみは「打つとおりのかな」で書きます。助詞の `は` `を` はそのまま
  `は` `を`、長音は `ー`
- 既定テーブルでは小文字の英字に規則があるため、よみに英字を入れると
  変換されてしまいます

現在のローマ字テーブルで打ち切れないお題は出題から外され、その名前が画面に
出ます。判定はテーブルの実シミュレーションなので、「次の入力」経由でしか
入力できないかなも打鍵可能として扱われます。お題ごとに探索するので、全件では
なく**出題数が埋まるまで**確かめます（お題を増やしても起動が重くなりません）。

かな以外の文字は、**選んだ配列で直接打てて、かつローマ字テーブルに規則が
無ければ**打てます。規則の無い打鍵はそのまま入力されるからです。

| | 既定テーブルでの例 |
| --- | --- |
| 打てる | 数字 `100`、大文字 `CPU`、記号 `%` `+` `?`、空白 |
| 打てる | 全角の `？` `！` `ＣＰＵ`（対になる半角のキーで。下記） |
| 打てない | 小文字 `abc`（`あbc` になる）、`.` `/`（`。` `・` になる） |
| 打てない | `ａｂｃ`（対になる `abc` も打てないため） |

### 全角・半角の記号

ローマ字テーブルは普通、対になる記号の**片方しか出せません**。既定テーブルなら
`?` は打てますが `？` は打てません。実際の IME は「記号を半角で入力するか全角で
入力するか」の設定を持っていて、もう一方は漢字変換で出します。だからテーブルは
片方だけで足りているわけです。

ここではその漢字変換の代わりに、**テーブルが片方しか出せない対に限り**、
打鍵で出た方をお題の側の文字として扱います。

| お題 | 打つキー | 入力欄に出るもの |
| --- | --- | --- |
| `ほんとう？` | `?`（Shift + `/`） | `ほんとう？` |
| `やった！` | `!`（Shift + `1`） | `やった！` |
| `ＡＢＣ` | `A` `B` `C` | `ＡＢＣ` |

お題と同じ文字が入力欄に出るので、見た目が食い違いません。

**両方出せるテーブルでは何もしません。** 打ち分けられるのに同一視してしまうと
練習にならないためです。対応するのは次の範囲です。

| | |
| --- | --- |
| 半角 `!`〜`~`（U+0021–007E） | 全角 `！`〜`～`（U+FF01–FF5E） |
| 半角空白 | 全角空白 |
| `~` | `〜`（波ダッシュ） |
| `¥` | `￥` |

位置ごとに見るので、同じテーブルで `?` と `？` の両方をお題に書けます。
`?` の箇所では `?` が、`？` の箇所では `？` が入力されます。

## 設定の記憶

読み込んだローマ字テーブルとお題は、**ブラウザに覚えておきます**。テーブルを
差し替えて使う人が、開くたびに読み込み直さずに済むようにするためです。
表示の設定と選んだ配列も一緒に覚えます。

保存するのは**読み込んだテキストそのまま**で、解析結果ではありません。
解析結果は素直に JSON にならないうえ、保存した後で解析部を直すと古い形のまま
残ってしまいます。テキストなら、そのときの解析部で読み直せます。

`localStorage` に置きます。キーは同じオリジンの別のアプリと混ざらないよう、
すべて `typing.` の下です。

| キー | 中身 |
| --- | --- |
| `typing.keyboardLayout` | 選んだ配列（JIS / US） |
| `typing.engine.table` | ローマ字テーブル（ファイル名とテキスト） |
| `typing.engine.problems` | お題（ファイル名とテキスト） |
| `typing.engine.options` | キーボード表示・ローマ字ガイド・ランダム出題・出題数 |

- 「既定に戻す」を押すと、覚えていたものを消して既定に戻します
- `localStorage` が使えないとき（プライベートウィンドウなど）は、記憶しない
  だけで動作は変わりません
- 1MB を超えるものは保存しません（保存できなかったことは画面に出ます）
- 保存したものが読めなくなっていたら、捨てて既定で起動します

## 操作

- 任意のキー … 開始
- BackSpace … かな 1 文字を取り消し
- Esc … やり直し
- Enter … 結果画面からもう一度

### BackSpace の挙動

IME と同じく、**画面に出ている入力の末尾 1 文字**を消します。お題の中なら
何文字でも戻れます。

1. 未確定のローマ字が残っているとき … その末尾 1 文字
   （`sha → しゃ` の定義で `sh` まで打った状態 → `s` が未確定で残る）
   （`った` に `tt` まで打った状態 → `っ` を残して `t` を消す）
2. 無いとき … 確定した入力の末尾 1 文字
   （`きゃ` を打った状態 → `き` まで戻る）

2 はローマ字ではなく**変換後の 1 文字（かな単位）**です。

消した結果、入力がお題と一致したら**そのお題は打ち切ったことにして次へ進みます**。
「あし」のつもりで `asyu` と打って「あしゅ」になり、BackSpace で「あし」に
戻したときなどです。そこで止まると、打ち終わっているのに進めなくなります。

消した結果、未確定文字がテーブルのどの規則の接頭辞でもなくなっても、
**未確定のまま残します**。次の打鍵で規則に合えば変換され、合わなければ
確定文字になります（変換できない打鍵と同じ扱い）。

```
ky      <TAB>        <TAB> きy
きya    <TAB> きゃ
```

このテーブルで `ky` まで打つと未確定文字は `きy`。BackSpace で `き` が残り、
続けて `ya` と打てば `きゃ` になります。

`きゃ` のつもりで `ki` と打ってしまった場合、BackSpace で `き` を消して
`kya` と打ち直せます。

戻った位置のローマ字表示は、そのかなに到達できる**最短の打鍵**に書き直されます
（例: `kya` から 1 回戻ると `ki` 表示になり、残りは `lya…`）。
BackSpace は打鍵数・ミス数には数えません。

IME はオフ（直接入力）にしてください。オンのまま打つと画面上部に警告が出ます。
